# Установка на общий сервер (рядом с другим проектом)

Облегчённая установка для тестового запуска на сервере, где уже работает другой сайт
(сейчас это `89.125.62.98`, на нём «Платформа для заказов»). Боевая схема на отдельном
сервере описана в [DEPLOY.md](DEPLOY.md).

## Как это устроено

- Всё, что относится к магазину, лежит в одной папке `/opt/ai-store`:
  `src/` (код), `.env` (настройки и пароли), `data/` (база, фото), `backups/` (копии).
- Магазин работает в Docker и слушает только внутренние адреса `127.0.0.1:3100` (сайт),
  `:8180` (API) и `:9100` (хранилище фото). Порты 80, 443, 3000 и 5432 он не занимает.
- Запросы принимает nginx сервера. Установка добавляет ему один файл
  `/etc/nginx/sites-available/ai-store.conf` для адресов `shop.optolink.uz`,
  `api.`, `media.` и `s3.shop.optolink.uz`. Настройки других сайтов не меняются.
  Если nginx не принимает новый файл, установка отменяет его и останавливается.
- У магазина своя база PostgreSQL в контейнере. Базу сервера (порт 5432) он не использует.
- Память: контейнеры ограничены примерно 3,5 ГБ в сумме, обычно занято около 1 ГБ.
- Режим `APP_ENV=staging`: письма и SMS не отправляются, коды входа пишутся в журнал.

Вне папки создаются только: файл nginx и два файла `/etc/nginx/snippets/ai-store-*`,
`/etc/cron.d/ai-store`, команда `/usr/local/bin/ai-store`, сертификат
`/etc/letsencrypt/live/shop.optolink.uz`. Docker ставится из пакетов Ubuntu, если его нет.

## DNS

В панели домена `optolink.uz`: A-записи `shop` и `*.shop` на IP сервера.

## Установка

На сервере от root:

```bash
mkdir -p /opt/ai-store
git clone https://github.com/J0ma2966/Ai_stor_platform.git /opt/ai-store/src
bash /opt/ai-store/src/deploy/shared/ai-store install shop.optolink.uz admin@optolink.uz
ai-store create-admin admin
```

Первая сборка идёт 5–10 минут. В конце команда печатает адрес сайта. Повторный запуск
`install` безопасен: пароли и данные сохраняются.

## Команды

| Команда | Что делает |
|---|---|
| `ai-store status` | состояние сервисов, ответы сайта и API, занятое место |
| `ai-store update` | копия базы, новый код из GitHub, пересборка, перезапуск |
| `ai-store restart` | перезапуск после правки `/opt/ai-store/.env` |
| `ai-store logs api` | журнал (`api`, `web`, `postgres`, `minio`); выход Ctrl+C |
| `ai-store backup` | копия базы и фото в `/opt/ai-store/backups` (и так каждую ночь в 02:10, хранится 7 дней) |
| `ai-store create-admin <логин>` | создать администратора панели `/admin` |
| `ai-store add-swap` | добавить 2 ГБ подкачки, если для сборки не хватает памяти |
| `ai-store prod` | боевой режим: настоящие письма с кодами, строгие проверки настроек |
| `ai-store staging` | вернуть тестовый режим |

Код входа при регистрации в тестовом режиме виден в журнале: `ai-store logs api`.

## Боевой режим

После установки магазин работает в тестовом режиме (`APP_ENV=staging`): письма не уходят.
Для реальных покупателей:

1. В `/opt/ai-store/.env` заполнить почту: `MAIL_PROVIDER=smtp`, `SMTP_HOST`, `SMTP_PORT`,
   `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` (адрес того же ящика). Для Gmail:
   `smtp.gmail.com`, порт `587`, пароль приложения (не пароль от аккаунта).
   Если хостинг закрывает исходящие почтовые порты (проверка:
   `timeout 5 bash -c '</dev/tcp/smtp.gmail.com/465' && echo открыт || echo закрыт`),
   письма отправляются по HTTPS через почтовый сервис: `MAIL_PROVIDER=brevo` (или `resend`),
   `MAIL_API_KEY` (ключ API сервиса) и `MAIL_FROM` (адрес отправителя, подтверждённый в сервисе).
2. По желанию: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` (вход и уведомления через бота),
   `GOOGLE_CLIENT_IDS` (вход через Google; в консоли Google разрешить источник `https://<домен>`).
3. `ai-store prod`.

Команда сначала проверяет, что почта заполнена. Если API в боевом режиме не запустился,
она показывает причину из журнала и сама возвращает прежний режим: магазин продолжает работать.
Прежний `.env` сохраняется рядом как `.env.bak`.

Оплата заказов идёт курьеру при получении, платёжные системы для этого не нужны.
Click и Payme используются только для покупки токенов AI-примерки; пока их ключи пусты,
приём платежей на сайте отключён.

### AI-примерка

Генерацию делает OpenAI, очередь работает внутри API (отдельный воркер и GPU не нужны;
одновременно `TRYON_WORKERS=2` генерации, API ограничен 1 ГБ памяти).

1. В `/opt/ai-store/.env` вписать `OPENAI_API_KEY=...` (ключ с platform.openai.com, на балансе
   должны быть деньги). Ключ никуда не пересылайте.
2. `ai-store tryon on` — проверяет ключ запросом к OpenAI, просит подтвердить риск, ставит
   `TRYON_PROVIDER=openai`, `TRYON_ENABLED=true`, `OPENAI_PROD_APPROVED=true`,
   `BIOMETRIC_STORAGE_COUNTRY` (по умолчанию `PL`) и `BIOMETRIC_FOREIGN_APPROVED=true`,
   пересобирает сайт и перезапускает. При неудаче настройки возвращаются как были.
3. Выключить: `ai-store tryon off`.

Фото тела и результаты лежат в отдельном закрытом бакете `boutique-biometric` того же MinIO
(через media-домен недоступен, только подписанные ссылки) и удаляются по срокам из
docs/TRYON.md. **Это биометрия:** закон РУз «О персональных данных» (ст. 27-1) требует
хранить её в Узбекистане, а OpenAI обрабатывает фото в США и хранит запросы до 30 дней.
Владелец принял этот риск 2026-11-14; для переноса в UZ — своё хранилище `BIOMETRIC_S3_*`
и `BIOMETRIC_STORAGE_COUNTRY=UZ`.

Токены: при регистрации начисляется `welcome_bonus` (по умолчанию 20 = одна генерация при
`generation_cost` 20), оба значения меняются в админке → Настройки; вручную — админка →
Пользователи → баланс. Покупка токенов через Click/Payme заработает, когда заполнены их ключи.

### Копия базы вне сервера

Ночная копия лежит на том же сервере и пропадёт вместе с ним. Чтобы копия базы уходила
ещё и в Telegram, заполните в `.env` `BACKUP_TELEGRAM_BOT_TOKEN` и `BACKUP_TELEGRAM_CHAT_ID`
(чат с ботом, которому вы написали `/start`, или группа с ботом) и проверьте: `ai-store backup`.
Файл шифруется паролем `BACKUP_PASSPHRASE` из `.env`. Сохраните этот пароль вне сервера,
без него копию не открыть. Расшифровка:

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -pass pass:ПАРОЛЬ -in db-ДАТА.dump.enc -out db.dump
```

Уходит только база (до 49 МБ, ограничение Telegram). Фото товаров остаются в копиях на сервере.

## Восстановление из копии

```bash
docker compose -p ai-store exec -T postgres pg_restore -U boutique -d boutique --clean --if-exists < /opt/ai-store/backups/db-ДАТА.dump
```

## Удаление

```bash
cd /opt/ai-store && ENV_FILE=.env docker compose -p ai-store --env-file .env -f src/deploy/shared/compose.yml down
rm /etc/nginx/sites-enabled/ai-store.conf /etc/nginx/sites-available/ai-store.conf /etc/nginx/snippets/ai-store-*.conf /etc/cron.d/ai-store /usr/local/bin/ai-store
nginx -t && systemctl reload nginx
```

Папку `/opt/ai-store` с данными удалите отдельно, когда убедитесь, что копии не нужны.

## Ограничения

- Сервер находится не в Узбекистане. Закон о персональных данных требует хранить данные
  граждан Узбекистана на серверах в стране; это риск владельца, перенос описан в DEPLOY.md.
- Один экземпляр сайта и API, без реплики базы: при поломке сервера магазин недоступен
  до восстановления. Вне сервера хранится только копия базы (если настроен Telegram).
- Нет мониторинга: стоит подключить внешнюю проверку доступности сайта.
- API работает под владельцем базы (в боевой схеме у него урезанные права).
