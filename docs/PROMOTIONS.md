# Реклама товаров магазинов

Магазин просит продвинуть свой товар, суперадмин включает рекламу, и товар появляется на
главной (сайт и Android-приложение покупателя) в карусели «Реклама». Карусель сама
перелистывает товары каждые 5 секунд.

Оплата рекламы пока вне системы: стоимость администратор согласует с магазином отдельно и
после этого одобряет заявку.

## Как это работает

1. **Магазин** подаёт заявку на опубликованный товар: срок показа (1–90 дней, в интерфейсе
   3/7/14/30) и комментарий для администратора. Сайт: кабинет магазина → «Реклама» или кнопка
   «Реклама» в списке товаров. Приложение магазина: карточка товара → «Заявка на рекламу».
   Пока заявку не рассмотрели, магазин может её отозвать.
2. **Суперадмин** (админка → «Реклама», по умолчанию открыт фильтр «На рассмотрении»):
   - «Одобрить»: даты показа, по умолчанию с сегодняшнего дня на срок из заявки;
   - «Отклонить» с причиной;
   - «Остановить показ» идущей или запланированной рекламы с причиной;
   - запустить рекламу без заявки: «Модерация товаров» → кнопка «Реклама» у опубликованного товара.
3. Магазин получает уведомление о каждом решении (`promotion_approved`, `promotion_rejected`,
   `promotion_stopped`) на сайте и в приложении магазина.

У товара может быть только одна открытая реклама: заявка на рассмотрении или одобренная
реклама, срок которой ещё не закончился. Проверка идёт под блокировкой строки товара.

## Состояния

В базе хранится `status`: `pending`, `approved`, `rejected`, `stopped`. В API добавлено
вычисляемое поле `state`:

| state | условие |
|---|---|
| `pending` | заявка ждёт решения |
| `scheduled` | одобрена, начало ещё не наступило |
| `active` | одобрена, `starts_at <= now() < ends_at` — показывается |
| `ended` | одобрена, срок закончился |
| `rejected` | отклонена |
| `stopped` | остановлена администратором (`ends_at` обрезан до момента остановки) |

Товар выпадает из карусели и сам по себе: если его сняли с публикации или заблокировали магазин.

## API

| Метод | Путь | Кто | Что |
|---|---|---|---|
| GET | `/v1/promotions` | все | товары с идущей рекламой (до 20, в формате каталога), кэш 60 с |
| GET | `/v1/store/promotions?state=&cursor=` | магазин | свои заявки и реклама |
| POST | `/v1/store/promotions` `{product_id, days, note}` | магазин | заявка; 409 `promotion_exists`, `product_not_published` |
| DELETE | `/v1/store/promotions/{id}` | магазин | отозвать заявку; 409 `promotion_decided`, если уже рассмотрена |
| GET | `/v1/admin/promotions?state=&store=&cursor=` | админ | все заявки |
| POST | `/v1/admin/promotions` `{product_id, days?, starts_at?, ends_at?}` | админ | реклама без заявки (по умолчанию 7 дней) |
| POST | `/v1/admin/promotions/{id}/approve` `{starts_at?, ends_at?}` | админ | одобрить; по умолчанию сейчас + `days` |
| POST | `/v1/admin/promotions/{id}/reject` `{reason}` | админ | отклонить, причина обязательна |
| POST | `/v1/admin/promotions/{id}/stop` `{reason?}` | админ | остановить идущую или запланированную; 409 `promotion_not_running` |

Срок показа: начало не раньше чем за сутки до текущего момента, конец позже начала и позже
текущего момента, не длиннее 365 дней. Все действия пишутся в журнал (`promotion.*`).

## Карусель

- Сайт: `web/src/components/PromoCarousel.tsx`, данные с сервера (`fetchPromoted`, кэш 60 с).
  Один товар на телефоне, два на экране от 900 px. Есть кнопки «назад», «вперёд» и «пауза».
  Карусель стоит при наведении, при фокусе внутри, когда она за экраном или вкладка скрыта.
  При «уменьшении движения» в системе нет ни автопрокрутки, ни анимации.
- Android: `mobile/app-client/.../Promo.kt` (`HorizontalPager`) — первая строка каталога на
  главной, только без поиска и фильтров. Стоит, пока пользователь листает, пока приложение
  свёрнуто, после «паузы» и при выключенной анимации в системе.
- Каждый слайд помечен «Реклама» (в Узбекистане рекламу нужно маркировать).

Миграция: `00050_promotions.sql` (диапазон рекламы 00050–00059).
